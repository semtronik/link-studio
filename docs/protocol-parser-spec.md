# Specification: Protocol parser system

## Goal

Allow the user to load a JavaScript file that decodes incoming LoRa frames
according to their proprietary protocol, annotates frames (correlation,
errors), and computes metrics (PER, latency, etc.).

## Architecture

### Data flow

1. A raw frame arrives from the serial port (hex string)
2. The app calls `decode(hex, context)` in the Worker → immediate return of decoded fields
3. The decoded frame is appended to the buffer
4. The app calls `analyze(frames)` in the Worker (periodically or per-frame) → returns annotations and metrics
5. The UI displays colored fields, per-frame annotations, and the metrics banner

### Sandboxing

The parser runs inside a dedicated **Web Worker**. It has access to:
- No DOM API
- No Tauri API
- No filesystem or network access

Only data passed explicitly via `postMessage` is accessible.

---

## Parser contract

A parser is a `.js` file that exports an object with the following properties:

### Required properties

| Property | Type | Description |
|----------|------|-------------|
| `name` | `string` | Protocol name displayed in the UI |
| `decode` | `function` | Decodes a single frame |

### Optional properties

| Property | Type | Description |
|----------|------|-------------|
| `version` | `string` | Parser version (semver) |
| `description` | `string` | Short description displayed in the UI |
| `analyze` | `function` | Analyzes the frame history for annotations and metrics |

---

## API: `decode(hex, context)`

Called for every incoming frame. Must be **stateless** and fast (< 1ms).

### Parameters

```typescript
interface DecodeContext {
  timestamp: number;  // Unix timestamp (seconds)
  rssi?: number;      // dBm
  snr?: number;       // dB
}
```

- `hex` (`string`): raw data in hexadecimal, no spaces (e.g. `"01002AFF3C10"`)
- `context` (`DecodeContext`): radio metadata for the frame

### Return value

```typescript
interface DecodeResult {
  // Decoded fields to display (required)
  fields: Field[];

  // Free-form data for analyze() (optional).
  // The app does not interpret it, it forwards it as-is to analyze().
  meta?: Record<string, any>;

  // Short summary shown in the "Decoded" column of the table (optional)
  summary?: string;
}

interface Field {
  name: string;            // Field name (e.g. "Temperature")
  value: any;              // Decoded value (e.g. 25.1, "DATA", 0x2A)
  unit?: string;           // Unit (e.g. "°C", "dBm", "%")
  bytes: [number, number]; // Byte range [start, end[ in the frame (0-indexed)
  color?: string;          // Highlight color: "blue" | "green" | "yellow" | "red" | "purple" | "gray"
}
```

### Example

```js
decode(hex, { timestamp, rssi }) {
  const type = parseInt(hex.slice(0, 2), 16);
  const seq = parseInt(hex.slice(2, 6), 16);
  const tempRaw = parseInt(hex.slice(6, 10), 16);
  const temp = (tempRaw - 4000) / 100;

  return {
    fields: [
      { name: "Type",        value: type === 1 ? "DATA" : "ACK", bytes: [0, 1],  color: "blue" },
      { name: "Sequence",    value: seq,                          bytes: [1, 3],  color: "yellow" },
      { name: "Temperature", value: temp, unit: "°C",             bytes: [3, 5],  color: "green" },
    ],
    meta: { type, seq },
    summary: `${type === 1 ? "DATA" : "ACK"} #${seq} T=${temp}°C`,
  };
}
```

## API: `analyze(frames)`

Called periodically over the entire decoded-frames buffer. May be expensive
(runs in the Worker).

### Parameters

```typescript
interface AnalyzeFrame {
  id: string;              // Unique frame identifier (generated by the app)
  hex: string;             // Raw hex data
  timestamp: number;       // Unix timestamp
  rssi?: number;
  snr?: number;
  decoded: DecodeResult;   // decode() result for this frame
}
```

- `frames` (`AnalyzeFrame[]`): all frames in the buffer, ordered chronologically (oldest first)

### Return value

```typescript
interface AnalyzeResult {
  // Per-frame annotations (key = frame.id)
  annotations?: Record<string, Annotation>;

  // Global metrics shown in the summary banner
  metrics?: Metric[];
}

interface Annotation {
  status: "ok" | "error" | "warning" | "info" | "linked";
  label: string;  // Short text shown in the status column (e.g. "ACK received (12ms)")
}

interface Metric {
  name: string;   // Metric name (e.g. "PER")
  value: string;  // Formatted value (e.g. "33.1%")
}
```

### Example: PER based on req/ACK

```js
analyze(frames) {
  const annotations = {};
  const data = frames.filter(f => f.decoded.meta?.type === 1);
  const acks = frames.filter(f => f.decoded.meta?.type === 2);

  let matched = 0;
  let totalLatency = 0;

  for (const d of data) {
    const ack = acks.find(a =>
      a.decoded.meta.seq === d.decoded.meta.seq &&
      a.timestamp > d.timestamp &&
      a.timestamp - d.timestamp < 5
    );

    if (ack) {
      const latency = Math.round((ack.timestamp - d.timestamp) * 1000);
      annotations[d.id] = { status: "ok", label: `ACK received (${latency}ms)` };
      annotations[ack.id] = { status: "linked", label: `Reply to #${d.decoded.meta.seq}` };
      matched++;
      totalLatency += latency;
    } else {
      annotations[d.id] = { status: "error", label: "Timeout - no ACK" };
    }
  }

  const per = data.length > 0 ? ((1 - matched / data.length) * 100).toFixed(1) : "0.0";

  return {
    annotations,
    metrics: [
      { name: "PER", value: `${per}%` },
      { name: "Avg. latency", value: matched > 0 ? `${Math.round(totalLatency / matched)}ms` : "-" },
      { name: "DATA sent", value: `${data.length}` },
      { name: "ACK received", value: `${matched}` },
    ],
  };
}
```

### Example: sequence-gap detection

```js
analyze(frames) {
  const annotations = {};
  const sorted = frames
    .filter(f => f.decoded.meta?.seq !== undefined)
    .sort((a, b) => a.decoded.meta.seq - b.decoded.meta.seq);

  let missing = 0;

  for (let i = 1; i < sorted.length; i++) {
    const gap = sorted[i].decoded.meta.seq - sorted[i - 1].decoded.meta.seq;
    if (gap > 1) {
      missing += gap - 1;
      annotations[sorted[i].id] = {
        status: "warning",
        label: `${gap - 1} frame(s) missing before`,
      };
    }
  }

  const total = sorted.length + missing;

  return {
    annotations,
    metrics: [
      { name: "PER (sequence)", value: total > 0 ? `${((missing / total) * 100).toFixed(1)}%` : "-" },
      { name: "Frames received", value: `${sorted.length}` },
      { name: "Frames missing", value: `${missing}` },
    ],
  };
}
```

## Parser management in the app

### Loading

- Parsers are stored in a dedicated app folder (e.g. `{appDataDir}/parsers/`)
- The user can load a `.js` file via an "Import parser" button in the UI
- The file is copied into the parsers folder
- A "Raw" parser is always available by default (displays raw hex without decoding)

### Selection

- A picker in the UI lets the user choose the active parser among loaded ones
- Switching parser re-decodes all frames in the existing buffer
- The selected parser is persisted in the preferences

### Validation

When loading a parser, the app checks:
- [ ] The file exports an object with a `name` property (string)
- [ ] The file exports a `decode` function
- [ ] `decode` called with a test hex returns an object with `fields` (array)
- [ ] If `analyze` is present, it must be a function

If validation fails, the parser is rejected with an explicit message.

### Runtime errors

- If `decode()` throws, the frame is shown raw with a "Parser error" annotation
- If `analyze()` throws, metrics and annotations are cleared, an error message is shown
- Errors are logged in the Worker console

## UI rendering

### Frames table

| Column | Source | Description |
|--------|--------|-------------|
| Time | `frame.timestamp` | Formatted timestamp |
| Hex | `frame.hex` + `fields[].bytes` + `fields[].color` | Raw bytes with per-field color highlighting |
| Decoded | `decoded.summary` or concatenated `fields` | Text summary |
| RSSI | `frame.rssi` | Signal |
| SNR | `frame.snr` | Signal-to-noise ratio |
| Status | `annotations[id].label` | Annotation from analyze() |

### Frame detail (on click)

- Hex view with each field highlighted in its color
- Field list: name, value, unit
- Full annotation if present

### Metrics banner

Bar at the bottom or top of the capture area showing the `metrics[]` returned
by `analyze()`.

```
┌──────────────────────────────────────────────────────────┐
│  PER: 12.5%  │  Avg. latency: 15ms  │  DATA: 48  │  ACK: 42  │
└──────────────────────────────────────────────────────────┘
```

## App ↔ Worker communication

### App → Worker messages

```typescript
// Load a parser
{ type: "load", code: string }

// Decode a frame
{ type: "decode", id: string, hex: string, context: DecodeContext }

// Analyze the full buffer
{ type: "analyze", frames: AnalyzeFrame[] }
```

### Worker → App messages

```typescript
// Load result
{ type: "loaded", name: string, hasAnalyze: boolean }
{ type: "load-error", error: string }

// Decode result
{ type: "decoded", id: string, result: DecodeResult }
{ type: "decode-error", id: string, error: string }

// Analyze result
{ type: "analyzed", result: AnalyzeResult }
{ type: "analyze-error", error: string }
```
